# sayori working profile

1. 更重视理论边界是否成立，而不是先产出文件或 schema。
2. 期待 agent 先从已有理论推导，不用浅层字段、目录或流程问题代替理论判断。
3. 偏好慢推进循环：agent 提问，user 回答，agent 生成，user review。
4. review lead 只应保留待审核内容本体：一个单一职责模块及其可审核断言。
5. lead 中不应加入解释、边界、来源、review 方式或流程许可。
6. “最小”指模块边界清楚、断言可审，不是字数少或只剩一句话。
7. agent 反复犯错和被纠正的模式可以成为 pick source。
8. 项目主线资产和用户层资产必须区分；改变项目主线的内容应回到 promote。
9. 默认使用中文、直接、少废话；必要技术名词可保留英文。
10. 对错误的容忍度取决于 agent 是否能吸收纠偏并修正后续判断。
